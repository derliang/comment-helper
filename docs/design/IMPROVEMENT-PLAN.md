## 3. 評語結構與改進計畫（C1）

- 結構固定為「肯定優點＋期待改進」；比重依**整體平均星等**，以**分句**為單位；大於 3 星優點較多，2.75～3.25 各半，小於 3 星改進較多；5 星與 1 星各留一小句另一面。分句配置表為暫定（`COMMENT-STRUCTURE.md`〈8〉）。
- 3 星以下：溫和期許；1～2 星的肯定句取分數最高的向度；全同分用態度類肯定語；全同分的改進項依「自律自重 → 日常生活 → 整潔 → 禮節 → 班級服務 → 待人誠信」；只禁「不」「缺乏」「差」「無法」等明確負向詞，掃出 11 條現有說法須改寫（`COMMENT-STRUCTURE.md`〈12〉）。
- 補充觀察優先：老師寫的事實必寫，其餘句數依比重調整。
- 改進計畫 P1～P4（順序是我的建議，使用者只說「列入」）：
  1. P1 星等比重結構，含全低分肯定句與全同分規則。
  2. P2 修 3 分段語法（例：「也整潔習慣已有基本表現」）與句尾套語去重。
  3. P3 蒐集真實觀察語料（使用者提供去識別化句子，只留句子不含姓名），量未辨識率，再擴充語意庫（現有 67 條內建規則）。
  4. P4 用瀏覽器量生成速度，再決定是否真的取消延遲。

**速度警告（我的實測，未在瀏覽器驗證）**：Node 下單次生成約 0.2～2 秒，個別組合到 7.9 秒。與「取消 0.9 秒延遲、評語立刻出現、按鈕在評語出來前停用」的決定有衝突風險，P4 要先做。

## 4. 備份、匯出與後續（B1）

- 還原前自動下載一份現況備份；標題列顯示「已 N 天未備份」，可直接點進「設定與備份 → 備份與還原」；衝突提示補上備份位置。
- 備份維持明文，下載時提醒保管。
- 「接受並下一位」＝已確認，接受後的評語可進正式匯出；之後可改，改了再接受一次。匯出前列出未接受名單，由老師選擇繼續或回去補。
- 匯出格式現行 Excel／Word 夠用；匯入名單使用者說目前沒有不順。
- 多分頁衝突加「重新載入最新資料」按鈕。
- 尚未承諾、不排程：雲端資料庫與帳號、跨裝置同步、模型微調、校方個資合規審查；有人要給其他老師用時再論，個資合規須先談（備份是明文含姓名，這是我的提醒）。
- **實作前須核對**：README 對「已確認」的說法前後矛盾（「正式匯出僅含已確認」對「不需逐筆確認即可下載」），我沒有實測哪個為準。
